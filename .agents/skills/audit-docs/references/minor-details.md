# Minor and obvious details

[Documentation audit](../SKILL.md)

Do not document every small behavior the code implements. Omit minor, predictable details that are readily apparent from reading the code.

## Checks

- Does the passage explain something readers cannot readily infer, or merely narrate the implementation?
- Would removing it lose a non-obvious contract, constraint, side effect, or rationale?

Delete obvious implementation notes rather than shortening them or turning them into feature lists. Preserve essential usage instructions and useful code-navigation links.
