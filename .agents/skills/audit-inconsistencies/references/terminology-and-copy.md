# Terminology and copy

[Consistency audit](../SKILL.md)

Compare the same concept across command descriptions, completions, views, tool cards, feedback, and user documentation.

## Checks

- Does a concept keep the same noun, verb, capitalization, and status wording across surfaces?
- Do action names distinguish alternatives from sequential operations, such as restoring text and then deleting its saved occurrence?
- Does tense distinguish a requested action, queued or running work, and a completed outcome? Does grouping or expansion change that meaning?
- Are API field names exposed where another surface uses a friendly label? Distinguish raw parameters and retained data from display labels.
- Are punctuation, units, plurals, key names, abbreviations, and empty-state tone coherent?
- Do documentation and command examples use the names users actually see?

## Evidence

Record paired strings with their surfaces and states. Identify whether wording is extension-owned or borrowed output. Recommend a canonical term only after checking that the concepts are equivalent. Preserve technical identifiers needed to configure or invoke an API.
