# Pi compatibility

[pi-editor-widgets](../README.md)

Verified against installed Pi **0.99.2** through package checks and offline host tests, including both renderers and selected-model compaction reserves with routed physical windows. Physical-terminal checks were not run. Public APIs do not expose other extensions' registries or row placement, so this extension uses narrowly scoped runtime hooks. No core or dependency edits are required.

## Upgrade checklist

1. Run [package checks and tests](../README.md#validation), including the shared [interactive host fixture](../../../libs/src/validation/interactive-host/README.md).
2. Verify `InteractiveMode.prototype.setExtensionStatus`. Discovery temporarily intercepts one random, never-registered key during `session_start`, obtains the real receiver before native side effects, and restores the method synchronously. The copied UI closures must still dispatch through that method, including when the extension is first enabled on `/reload`.
3. Verify `extensionWidgetsAbove`, `extensionWidgetsBelow`, `footerDataProvider`, region/editor/status/pending containers, `renderWidgets`, and `setExtensionFooter`. The capability check must fail with a diagnostic rather than silently lose contributors. Native maps must still own factory invocation, same-key replacement, disposal, and unregistration. The coordinator reproduces native widget spacing (one blank line above the editor, even when empty; none below) and calls `renderWidgets` to restore native containers on release.
4. Verify `renderer`, the stable `ui` proxy, and `switchTuiMode`. The coordinator hooks the actual renderer's `requestRender`, restores it when Pi replaces the renderer, and rebinds after switching modes. Its public `mode` property gates fullscreen context/token toggling and restores the original regular-mode displays. Region invalidation must still reach borrowed native components.
5. Verify custom-footer storage, reset order, and branch subscription disposal. Existing custom footers must prevent acquisition; later replacements must release the coordinator without being overwritten during cleanup.
6. Verify container mouse dispatch. Pi 0.99.2 propagates the native `target` geometry and optional `focusTarget` for capture/focus; coordinate translation must not focus otherwise passive components. Forward each copy's render width, not its occupied hit-area width: native containers validate cached child layout against the event width. A handled primary press must retain the usage widget's target across redraws until release so Pi synthesizes one click.
7. Verify session shutdown/start and reload ordering. Shutdown releases adapters but does not dispose borrowed widgets. Native UI reset owns disposal. New starts load preferences and must not retain stale session components.
8. Verify metric APIs: `getSessionStats()` includes usage, tool-result, compaction and branch-summary entries; latest assistant prompt usage determines cache-hit percentage; `getContextUsage()` preserves unknown post-compaction counts and returns no usage when the effective model's window is unknown; never render that unknown window as zero; `autoCompactionEnabled` is runtime state; `settingsManager.getCompactionReserveTokens(session.model)` resolves the selected model's reserve for the verbose threshold and can reject invalid settings. Pi's `_exceedsCompactionThreshold` and `_checkCompaction` combine this selected-model reserve with the physical window, even when a different reserve is configured for the physical model. The label remains the selected model's identity; subscription reporting remains native. Check subscription reporting, thinking support, session names, home abbreviation, and native git branch representation.
9. Verify custom UI mounting through the shared [responsive host](../../../libs/src/tui/responsive-custom-ui/README.md) and perform the [terminal checks](testing.md#terminal-checks).

## Limitations and replacement opportunities

- Mouse input is available only in fullscreen mode. Context and token usage use `MouseRegion` to claim primary presses and toggle independently on Pi's synthesized click without taking focus. Regular mode keeps the original non-interactive usage displays.
- A custom footer is exclusive, not composable. Use native widgets/statuses for contributors or disable the competing footer extension.
- Duplicated placements share one native instance and render at the same terminal width. Mouse dispatch must use that width rather than the compacted hit-area width. Drag capture after a later frame follows the component's most recent render geometry.
- Components expose `render(width)`, not preferred-size metadata. Each placement renders once at the terminal width; occupied output determines its row width, and whole widgets wrap in order without shrinking. A full-width component occupies its own row. Widgets control wrapping within their own output. While `/widgets` is open, the menu sizes itself from the unclipped region height, so tall regions still clip on short terminals.
- Shared rows compact only literal trailing spaces whose terminal state is known not to paint or carry metadata. Backgrounds, decorated spaces, and unknown escape sequences retain their width. Leading indentation and singleton padding are not removed. Pi's renderer already expands visible tabs to the three columns used by `visibleWidth()` before terminal output; the extension must not rewrite tabs inside OSC/APC payloads.
- Automated fixtures use real Pi renderers and the native fullscreen dock without startup downloads, process signal handlers, or a physical terminal. They do not establish visual quality for every component or terminal emulator.
- Prefer a future public registry/layout or renderer-lifecycle API over the corresponding private hook. Replace the boundary and its tests together, without transitional adapters.
