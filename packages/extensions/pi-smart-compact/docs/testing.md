# Testing specification

[pi-smart-compact](../README.md)

## Observable contracts

- `context_window({})` reads the execution context's `getContextUsage()` without initiating compaction. Its model-facing JSON and structured details preserve the native object without added fields, rounding, or replacement of `null`. An `undefined` result produces `Context usage unavailable.` with undefined details.
- `compact({ instructions? })` requests a one-shot operation, not a completed result. Its model-facing acknowledgement is always `Compaction requested.` Model overrides retain `details.modelOverride` and `details.thinkingLevel` for display-only annotation by `pi-tool-display`; unconfigured calls keep `{ scheduled: true }` details. The level is explicit configuration or the session's current level, except non-reasoning models default to `off`. Saved acknowledgements describe the configuration at request time, not current settings. Requests are isolated by session; duplicates coalesce with last-request-wins focus, and settlement/disposal/abort cannot leak them into another run.
- Successful compaction uses the native compaction entry and summary: no extra success status message is emitted, persisted, or added to model context. Skipped attempts (with reason), reported cancellations, and reported failures (with error) produce one persisted, visible `pi-smart-compact.result` message before any next model response. No request means no status message; duplicate requests produce at most one. Status messages survive context rebuilding without adding user prompts or requesting another turn.
- Each successful default summary (tool, manual, threshold, or overflow) saves one `pi-smart-compact.model` custom entry directly before its compaction entry, recording the summarizing `provider/model-id`, generation-time thinking level, and trigger. It never enters model context and keeps the compaction entry as the branch leaf. Unrelated summary calls, hook-supplied summaries, summarization failures, and cancellations before native persistence save none. A thinking-level change during generation must not change the recorded level.
- Summary-model rendering ignores malformed stored data and sanitizes model identifiers for plain terminal display without changing stored identifiers.
- A session without a pending tool request follows Pi's original between-response boundary. Explicit requests bypass threshold/enable checks but preserve current-model compaction settings and complete tool-batch persistence.
- Global settings merge field-by-field with trusted cwd settings only. Absent fields retain native model/thinking selection; invalid participating files/values or unknown extension keys fail closed. Reading is bounded to 1 MiB and never writes settings or searches ancestors.
- A configured model handles the tool's default history and split-turn summaries, including native retries. It uses its own provider authentication (key, headers, environment, and base URL) and output cap while preserving native provider retry limits and request/connection timeouts, including provider-timeout precedence and disabled HTTP idle timeouts. Native `before_provider_headers` handlers can add or remove selected-provider headers after authentication, once per summary attempt including retries. Explicit thinking overrides apply only to the native operation; unsupported levels fail. No override changes the conversation model/thinking, non-opted-in automatic or manual compaction, unrelated model requests, or hook-supplied summaries. Selected-model lookup/authentication/generation failures do not fall back to the active model.
- Omitted or false `applyToManual` leaves `/compact` unchanged. True applies configured model/thinking to native `/compact`, RPC, and SDK manual summaries without changing their instructions or lifecycle. The flag alone leaves manual summaries unchanged, including with a read-only stream function; flag-only tool requests likewise use the native path when no instructions are supplied.
- Omitted or false `applyToAuto` leaves threshold and overflow compaction unchanged. True applies configured model/thinking to both automatic reasons without changing hooks or lifecycle; it never routes tool requests or `/compact`, and `applyToManual` never routes automatic summaries. Flag-only automatic compaction leaves the stream untouched, including a read-only stream. An unavailable model fails the automatic attempt without fallback or a compaction entry; native recovery edits are not undone.
- Default history-only, prefix-only, and mixed summaries receive focus exactly once. Omitted/empty instructions add no focus. Real retries reuse an unmodified original request. Hooks see the same focus and can cancel or replace native summarization.
- Tool-requested compaction remains inside the active run: no extra user prompt, early idle resolution, duplicate start/settlement, or premature print exit. Native reasons are `manual`, including retries and failures. Success updates the next model request and saves native usage/file metadata.
- Reported tool-requested failure/cancellation leaves old context intact. Actual abort prevents another main-model request. Skipped compaction still consumes its request and restores temporary overrides. A native attempt returning without an outcome event gets a neutral explanation, not an unsupported diagnosis that the session was too small.
- Unexpected native exceptions propagate without a status message. Outcome event listeners are released on every exit; disposing a binding during an attempt prevents late outcome publication.
- The summary-model persistence wrapper waits until native `appendCompaction`, after Pi's final abort check. It deactivates on persistence, abort, terminal compaction events, or binding disposal, and leaves later replacements untouched.
- Temporary summarizer, event, and stream wrappers deactivate after all outcomes; cleanup restores original identity/property ownership only for hooks still owned. The shared boundary restores after its final owner exits unless replaced by another patch, and rejects unsupported implementations or conflicting ownership.

## Coverage boundaries

- Configuration tests cover absent/optional fields, normalization, trusted field inheritance, ignored untrusted files, cwd-only lookup, malformed/oversized/unreadable files, strict extension keys, and boolean `applyToManual`/`applyToAuto` validation/inheritance (including a project disabling a global opt-in). Unit tests exercise request isolation, one-shot consumption, explicit clearing, signal/run aborts, swallowed native preparation errors (including a failing diagnostic branch read), unexpected native exceptions, duplicate bindings, compatibility rejection, and boundary ownership restoration.
- Bundled CLI subprocess tests inspect provider requests, event traces, next-response context, and reopened session files. Dedicated-provider cases verify credential isolation, header-hook additions/removals and dispatch counts, provider retry/timeout settings in request options (including provider timeout precedence and disabled HTTP idle timeout), selected-model output caps, explicit/inherited thinking and non-reasoning defaults in provider requests and saved acknowledgements, failure without fallback, custom-hook precedence, and restoration after success, retry, failure, or cancellation. They cover text/JSON continuation, all summary shapes, retries, empty focus, custom summaries, hook/compaction-only cancellation, failure, abort, duplicate requests, and too-small contexts. Successful attempts must have no extra status message in events, model context, or the reopened session; reopened sessions contain the expected summary-model entry before each default compaction, including native manual and threshold entry points. For non-success attempts, the status must persist in the reopened session and appear in any subsequent provider request; native message events must publish it before any final response.
- A real API/SDK host verifies `context_window` registration and execution across session replacement/reload. Controlled native usage results cover unchanged numeric values, null usage, and unavailable usage. It also verifies compaction, continuation, native summary visibility without a redundant success notice in a later user-requested turn, fresh-session replacement, extension reload, and final boundary cleanup. Configured and unconfigured runs verify that native fallback follows active-model switches and that removing settings takes effect on reload, including the persisted tool acknowledgement and model-override metadata. Provider requests retain the plain acknowledgement without a model annotation, including serialized compaction prompts. Main, configured summary, and reentrant requests retain header-hook modifications. A reentrant summary with a different abort signal must receive neither injected focus nor model routing even while a native summary is in progress. It independently exercises the API-module fingerprints rather than the bundled CLI implementation.
- Renderer tests cover model labels, malformed stored metadata, and terminal-control sanitization. They do not establish visual appearance.
- SDK metadata cases verify generation-time thinking, exclusion of unrelated summary calls, late cancellation without orphan entries, and restoration when another wrapper retains the append hook. Default manual, threshold, and overflow summaries verify entry attribution and adjacency; hook summaries and failed attempts add no metadata.
- SDK cases verify omitted/enabled manual and automatic opt-ins independently, thinking-only and flag-only settings (including a read-only stream through manual and automatic attempts), native instructions, header hooks, retries, failure without fallback, hook cancellation/custom summaries, compaction abort, and final shared-router cleanup. Direct threshold and overflow entry-point calls verify routing with and without `applyToAuto` (including an unavailable model), per-attempt terminal events and persistence, the overflow continuation flag, and stream/idle restoration. Removing settings on reload restores native selection for manual compaction and both automatic reasons.
- Bundled CLI cases exercise the native manual and threshold entry points, each with its flag absent, false, and true while the other flag is enabled, including dedicated-provider credentials, thinking, output caps, persistence without status/continuation messages, and wrapper cleanup. A flag-only CLI tool case verifies native model selection and continuation.
- Fixtures use offline providers and disposable system-temp workspaces. No personal settings or credentials are used; no provider network calls are made. Tests check prompt plumbing and lifecycle, not whether a real model follows instructions faithfully.

## Manual checks and exclusions

Interactive progress rendering, Escape interaction, real-provider adherence/quality, and arbitrary third-party concurrent patch combinations require separate checks. Automatic routing tests invoke native entry points directly; they do not exercise threshold detection or the full overflow retry scheduler. The extension does not own Pi's summarization algorithm or provider behavior; tests protect adapter boundaries rather than duplicating native algorithm coverage.

Run [validation commands](../README.md#validation) and follow [workspace testing](../../../../docs/agents/testing.md).
