# Subagent terminal validation for maintainers

[pi-subagents](../README.md) · [Test coverage](testing.md)

Use the [offline terminal launcher](../README.md#validation) with `delegate-display` for wide characters, control sequences, and a 12-line prompt; use `delegate-slow` for a running card. Use completed [tasks](../GLOSSARY.md#tasks-and-processes) for list paging. The launcher loads only `pi-subagents` and its offline provider. Use Pi's default keybindings for the existing procedures below, except in the remapped-controls procedure.

## Remapped controls

Edit `agent/keybindings.json` in the fixture directory that the launcher prints. Repeat these checks in regular and fullscreen modes, with a task transcript and a job log available. Restore default bindings before the other procedures. The [control rules](interface.md#panel-keys) define precedence and local actions.

| Do                                                                                                                                                                           | Expect                                                                                                              |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Remap `tui.select.up` and `tui.select.down` to **K** and **J**, and `tui.select.pageUp` and `tui.select.pageDown` to **U** and **D**. Use them in the list and both viewers. | The new keys select or scroll; the old keys no longer invoke those panel actions.                                   |
| Remap `tui.select.confirm` to **F7** and `tui.select.cancel` to **F6**. Open a task or job, return to the list, then close it.                                               | The new keys open the item, return to the list, and close the panel, and the footer names them.                     |
| At 40 columns and ten rows, remap navigation to **Ctrl+Shift+Up** and **Ctrl+Shift+Down**.                                                                                   | The close hint stays visible before navigation hints.                                                               |
| Remap `app.tools.expand` to **F8** and press it in the task viewer.                                                                                                          | Only the task viewer's messages change expansion.                                                                   |
| Change a binding while a view is open, after Pi loads the new configuration.                                                                                                 | The next input and rendered hint use the new binding without reopening the view.                                    |
| Give both cancel and confirm only **F6**, then press it in the list.                                                                                                         | The list closes; the inspect hint says "unavailable".                                                               |
| Give `tui.select.down` only **Ctrl+D** and select an active task.                                                                                                            | **Ctrl+D** selects downward; the abort hint says "unavailable".                                                     |
| Remove all bindings for `tui.select.up`, then press **Up**.                                                                                                                  | Selection stays unchanged, and the hint says "select up unavailable".                                               |
| Give cancel only **Ctrl+C**, with no other panel action bound to it, then press it in the list and both viewers.                                                             | Pi handles **Ctrl+C**; the panel does not treat it as back or close, and the corresponding hint says "unavailable". |
| With key-release events enabled, press and release one navigation key, then the expansion key.                                                                               | Each press performs one action; its release performs none.                                                          |
| With no configured binding that conflicts, use **Tab**, **Shift+Tab**, **Ctrl+B**, and **Ctrl+D** in the list, then **Home** and **End** in a viewer.                        | The local actions retain their documented behaviour.                                                                |

## Background results

The `background-late` and `background-input` children reply only after `run-release` exists in the work directory. Delete it before each check that uses either scenario.

| Do                                                                                     | Expect                                                         |
| -------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Run `background-late`.                                                                 | The working message includes "Waiting for background results". |
| Press **Esc** during the wait.                                                         | The component clears; the wait ends and the task continues.    |
| Create `run-release`.                                                                  | The result starts a new turn.                                  |
| Run `background-late`, then type `reply` during the wait.                              | The input is processed at once.                                |
| Create `run-release`.                                                                  | The result arrives.                                            |
| Run `background-slow`, then send `abort-id <task_id>` in regular and fullscreen modes. | The card has the `subagent` layout with `⊘ aborted`.           |
| Click the abort card.                                                                  | The task opens.                                                |
| Run `background-input`, then send `update-id <task_id> steer`.                         | The update returns immediately.                                |
| Create `run-release`.                                                                  | The task's background result contains the added input once.    |
| Let a background result arrive.                                                        | It shows in Pi's default message box.                          |

### Job log retention

Run the offline launcher in regular mode, then repeat in fullscreen mode. In a second terminal, set `fixture` to the printed disposable workspace path and remove `"$fixture/work/job-release"` before starting. The fixed `job-retention` scenario writes 64 MiB in paced chunks, then waits for that file. Set `log` to the log path on its job card. This is a manual check of the [retention policy](jobs.md#log-files); it has no automated test.

| Do                                                                                      | Expect                                                                                  |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Run `job-retention`, then open its job log from `/subagents`.                           | The job stays active while output arrives.                                              |
| Run `wc -c < "$log"` repeatedly while the job writes.                                   | The file never exceeds 16,777,216 bytes, including its marker.                          |
| Keep the viewer open through the compactions.                                           | The newest output becomes visible, ending with `Fixture retention checkpoint 64`.       |
| Press **Home** after that checkpoint appears.                                           | The first displayed line is `[Earlier output omitted: N bytes]`, with a positive count. |
| Read the first line with `head -n 1 "$log"`.                                            | Its omitted-byte count matches the viewer.                                              |
| List `"$fixture/tmp"` after the output stops.                                           | There is one `pi-job-*.log` file and no `pi-bash-*.log` file.                           |
| Press **End**, then run `touch "$fixture/work/job-release"`.                            | The viewer adds `Fixture retention complete` and shows `completed` with exit code 0.    |
| Close and reopen the log, then press **Home**.                                          | The omission marker remains available in the saved log view.                            |
| Exit Pi, check that the fixture processes stopped, and remove the disposable workspace. | No fixture process or log remains.                                                      |
