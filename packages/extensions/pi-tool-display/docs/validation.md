## Automated checks

Run the affected packages, including both consumers of the shared classifier:

```sh
for package in pi-tool-display pi-fff-guard @pi-mono/utils; do
  vpr "$package#format" --check
  vpr "$package#check"
  vpr "$package#test"
done
```

## Terminal procedure

Use disposable working/agent directories and an offline scripted provider issuing real tool calls. Launch the installed **`pi` executable** in both `--tui-mode regular` and `--tui-mode fullscreen`. Directly running `dist/cli.js` does not test the published bundle: extension imports see different method bodies there.

- Issue adjacent reads/searches/lists, including `a.ts → b.ts → a.ts`, visible assistant boundaries, failures, cancellation, and overlapping calls. Compact summaries must retain each invocation, including repeated reads, and expose established failure counts. Notices and diagnostics must appear beneath their owner, before the next tool; expansion must retain all calls/results.
- Use the configured global expansion action and fullscreen group clicks. Resize and scroll before clicking again. Check dark/light themes, narrow rows, link priority, drag selection, clipboard behavior, wheel scrolling, and the absence of mouse capture in regular mode.
- Confirm that default settings hide native/FFF parameter blocks even after expansion, while summaries, results, and generic arguments remain visible. With FFF multi-search enabled (`PI_FFF_MULTIGREP=1`), check that expanded cards retain all `patterns` and `constraints` in their summaries. Enable `showParameters`, reload, then verify a trusted project's explicit `false` overrides global `true` and omission inherits. With parameters enabled, expand structured parameters and check their straight `│` rules through soft wraps when a visible result follows; otherwise expect indentation without a rail. Check `├` for earlier result items and `└` for the final sibling, with related warnings and all diff hunks remaining continuations. Compare dim structure against readable values in both themes; include escaped JSON strings, nested arrays, header annotations, compact omission hints, and failure/timing metadata.
- Compare accented grouped `Read`/`Search`/`List` labels against neutral card titles and dim tree rules in both themes. Compare native empty output, failure/timeout/cancellation diagnostics, failed-change proposals, FFF no-match/count/fallback diagnostics, and typed MCP outcomes against the [semantic color policy](renderers.md#semantic-colors). Check expanded metadata and saved-output references. FFF cursor instructions, routine limit hints, and page numbers must stay hidden in compact and expanded cards, including after reload; retained results must still contain the pagination data. Literal process output resembling a placeholder/status must retain its ordinary styling.
- Include image-bearing grouped siblings with image display enabled/disabled. Native image protocols should emit each image once; unsupported protocols should retain an image notice without restoring redundant text.
- Exercise streaming output above Pi's retained-result limit, authoritative final replacement, saved-file expansion, missing/oversized saved output, file creation/overwrite, and unavailable/failed diffs. Include one-line edits in files above the 64 KiB observation limit and small overwrites above 1,000 lines: usable patches must remain visible without observation-budget warnings. Reopen histories containing both a valid native patch and an old budget warning. Include BOM-bearing files, split multibyte output, and literal trailing U+FFFD; decoding must not invent file changes or discard valid output. Reopen a history with more than eight saved-output calls; expand a late card after earlier reads finish and confirm its available output loads. Duration/exit facts must describe observed operations, not inferred command text or preflight time.
- For the [diff viewer](renderers.md#diff-viewer), check unlabeled side-by-side columns for mixed edits in both compact and expanded cards. Addition-only/deletion-only edits and all write patches, including overwrites, must stay unified at every width and expansion state. Write patches must omit the `+/-` count summary while retaining line markers and application diagnostics; edit counts remain visible. Hunk labels must omit raw patch ranges. Resize below the 40-content-columns-per-side threshold and back. Include unequal additions/deletions, multiple hunks, missing-final-newline markers, long wrapped lines, tabs, emoji, and combining marks. Confirm added/removed row backgrounds and stronger inline highlights preserve syntax colors in both themes without leaking into the separator, empty cells, or subsequent content. Include edits in the middle of long Markdown context and long shared line prefixes: compact mode must show the first actual edit, rather than only unchanged head/tail rows. Single-hunk patches must have no hunk label in either compact or expanded mode. Check complete focused diffs at the 30-changed-row boundary with additional surrounding context, first-hunk previews with remaining-hunk counts, and all numbered hunks with full wrapping after expansion. Retained history must display without reading today's files.
- Reload twice, create/resume a session, restart, fork, navigate the tree, compact, and remove the extension. Verify current settings/branch selection, native ownership/active tools, historical expansion, and new calls after each change. Inactive/disposed displays must not animate or invalidate a replacement session.
- Create persisted print/JSON/RPC sessions, then reopen each in the TUI. There must be no automatic display entries from non-TUI execution, no replayed calls, and no invented before-states or timing. New interactive calls can collect facts normally.
- Exercise user `!`/`!!` success, failure, cancellation, expansion, and context exclusion. These remain Pi shell cards and never join groups or acquire display observations.

Use a host with the PowerShell backend for real PowerShell execution. Do not equate portable construction checks or emitted image-protocol sequences with platform execution or visible image rendering.

## Platform coverage and remaining gaps

Validation targets Pi **0.85.1** and official FFF **0.10.6**. Recorded Linux tmux coverage includes regular/fullscreen rendering, edit/write/read/shell action headings paused during argument streaming and middleware queueing, cwd-relative file labels and absolute outside labels through grouping/expansion/reload (including outside reads and writes), mouse clicks after scrolling/resizing, dark/light themes, parameter settings, FFF searches, native mutations, shell streaming/truncation, saved-output expansion, and lifecycle reconstruction. Offline checks also cover blocking/result middleware, non-TUI sessions, and user `!`/`!!` success, failure, cancellation, and context exclusion.

The git-diff-view integration has additional installed-executable tmux coverage in regular/fullscreen modes: compact/expanded patches, reflow from 120 and 157 columns to 72, dark/light row backgrounds and inline highlights, Unicode, multiple hunks, two reloads, and subsequent native overwrite/failed-edit calls. Disposable retained-session copies also verified the first changed regions in Markdown paragraphs and test-name edits at 157×39 and 72 columns, including compact hunk headers, remaining-hunk notices, full expansion, theme changes, and reloads. Automated cases cover focused diffs at the row-limit boundary, complete first hunks, paired excerpts, long-line wrapping, missing-newline markers, and sparse high line numbers.

The jsdiff change has installed-executable tmux coverage in both TUI modes: native edits above 64 KiB, one-line overwrites in 2,500-line files, compact/expanded layouts, dark/light themes, 180→72-column reflow, and writes after reload. Reopened sessions preserved patches after result middleware replaced the native result, suppressed injected old budget warnings beside valid native patches, and left deliberately changed current files untouched without replaying calls.

The ownership-based tree layout has installed-executable tmux coverage in both TUI modes with real native calls and official FFF 0.10.6. Checks covered per-call diagnostic ownership, repeated reads, per-call failures, native image fallback between calls, separate typed MCP items, middleware-rejected edits, oversized-write observation notices, dark/light themes, 140→72-column reflow, and parameter expansion. Fullscreen summary clicks and notice clicks after scrolling/resizing expanded the correct group. Reloads retained the layout and supported new searches; reopened sessions kept all 13 results without replaying calls or replacing retained patches with deliberately changed current files.

FFF pagination suppression has additional installed-executable coverage in both TUI modes with real find, grep, and multi-search results: compact/expanded cards, dark/light themes, 120→72-column reflow, process reopening, and reload. Cursor instructions and routine limit/page notices stayed hidden while search matches and expanded counts remained available. All eight results per session were retained without replay; all four searches kept their original cursor data in both session history and the offline provider's model context.

Visible Kitty/iTerm images, link activation, drag/clipboard behavior, and Windows/PowerShell execution remain unverified. Unsupported-image fallback has tmux coverage; component tests check both no-image and Kitty emission paths, including joined grouped siblings. Emitted protocol sequences do not establish visible image rendering. Real PowerShell validation requires an available `pwsh` backend.

Inherited limits remain: temporary output files can disappear, external writers can race with Pi's queue, and old sessions cannot recover facts never recorded. Resource budgets and side effects are documented in the [README](../README.md#observation-and-saved-history).
